# 原型能力实验看板：实验设置摘要设计

## 目标

在本地实验看板中直接说明排名产生的实验条件，让读者在查看跨输入比较和单项排名前，能够快速理解输入、参测能力及来源、执行主体与方式、评分维度。

## 展示位置与形式

- 在页面说明文字之后、现有“跨输入比较”之前新增“实验设置”区域。
- 使用四张响应式摘要卡，分别对应：输入、参测 Skill 及来源、执行主体与方式、评分维度。
- 桌面端多列排列，窄屏自动改为单列；沿用现有深色卡片、边框和文字层级，不引入新的交互或依赖。

## 展示内容

### 输入

- 穿搭 Tab 迭代方案。
- AI 试穿相机上传 PRD。
- 两份飞书文档均固化为独立本地输入，供各实验单元重复使用。

### 参测 Skill 及来源

- Open Design：本机安装的 Open Design 桌面应用内置能力。
- huashu-design：下载到实验环境的本地 Skill 包。
- prd-generator：安装在本机 Codex Skills 目录中的本地 Skill。
- pm-kakaxi-skills：安装在本机 Codex Skills 目录中的本地 Skill，作者标记为 `pengmingyu`，版本 `2.1.0`。
- vne-prototype：安装在本机 Codex Skills 目录中的本地 Skill，版本 `1.0.3`。
- inspire-prototype：由全局安装的 `@byted-inspire/prototype-cli` 提供的内置 Skill。
- 本批六个参测项中没有直接从 GitHub 仓库运行的 Skill；来源按实际安装形态展示，不把依赖包的 GitHub 地址误记为 Skill 来源。

### 执行主体与方式

- Codex 主 Agent 负责编排、实验约束、汇总与统一验收。
- 独立 Subagent 按“一个输入 × 一个 Skill”执行实验任务。
- 平台型 Skill 通过各自原生 CLI、MCP 或托管生成流程产出原型。
- 共设置 12 个隔离实验单元，即 2 份输入 × 6 个 Skill。
- 每个单元只读取自身输入和对应 Skill 允许使用的资源，不读取其他实验单元的产物。
- 按各 Skill 自身标准流程生成，不人为统一技术栈、页面数量或视觉风格。
- 对实际产物执行固定任务和浏览器验证；失败、阻断或偏离均保留记录。

### 评分维度

- 需求忠实度：20 分。
- 流程覆盖：15 分。
- 交互：20 分。
- 视觉层级：15 分。
- 边界状态：10 分。
- 稳定性：10 分。
- 交付质量：10 分。

## 数据与实现边界

- 实验设置是本批实验的固定配置，不从单个 `result.json` 推导，统一由看板构建脚本生成。
- `comparison/native-experiment/data.json` 新增结构化 `experimentSettings` 字段，HTML 只负责渲染。
- 不改变现有评分、排序、原型链接、偏离记录或适用性数据。

## 验证标准

- 看板首页在“跨输入比较”之前显示“实验设置”。
- 四项设置均完整呈现，中文标签与本规格一致。
- 数据文件包含结构化实验设置，页面不复制另一份硬编码内容。
- 现有看板测试继续通过，并增加实验设置字段与四张摘要卡的回归断言。
- 在本地静态服务中验证桌面和窄屏布局可读，现有全部原型链接不受影响。
