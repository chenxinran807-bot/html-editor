# 抖音商城独立端穿搭 Tab 设计说明

## 1. 目标

设计一个面向抖音商城独立端的「穿搭」Tab，以双列穿搭瀑布流承载内容探索，并通过整套入口、详情换款和整套购买缩短成交路径。

首要目标是促进整套穿搭成交；内容浏览和停留是辅助目标。

## 2. 原型范围

本轮包含：

- 穿搭 Tab 首页。
- 场景筛选与双列穿搭瀑布流。
- 穿搭详情页。
- 单品勾选、取消选择及相似款替换。
- 已选单品加入购物车与购买反馈；默认全选时即为整套成交。
- 加载、空态、图片失败、商品失效、部分售罄和替换失败状态。

本轮不包含：

- 真实支付、登录、购物车或推荐接口。
- 新增或修改设计语言核心资产。
- AI 试穿、用户身材档案和个性化搭配生成。
- 商家、达人发布与内容审核后台。

## 3. 信息架构

### 3.1 穿搭 Tab 首页

页面从上到下包含：

1. 顶部标题与商城通用操作区。
2. 场景筛选 Tab，首批使用中性场景文案：推荐、通勤、约会、显高。
3. 双列穿搭瀑布流。
4. 商城底部 Tabbar，穿搭处于选中态。

### 3.2 穿搭卡

每张卡包含：

- 3:4 穿搭主图，等比裁切，加载失败时使用同尺寸占位。
- 风格标题，最多两行，超长截断。
- 整套件数。
- 整套价格；原型使用明确标注的演示数据，不表达真实优惠。
- 「查看整套」入口，整卡同时可点击进入详情。

卡片不展示未经数据支持的销量、好评、折扣、限时或“最低价”等营销信息。

### 3.3 穿搭详情页

页面从上到下包含：

1. 返回与分享操作。
2. 完整造型主图与穿搭标题。
3. 本套单品列表。
4. 每件单品的图片、标题、规格、价格、选中状态与「换一件」入口。
5. 底部固定成交栏：已选件数、合计价格、「加入购物车」和动态文案「购买整套」/「购买已选」。

## 4. 核心交互

### 4.1 浏览与筛选

- 点击场景 Tab 后更新当前选中态和瀑布流内容。
- 页面保留当前滚动位置；返回已访问场景时恢复该场景位置。
- 内容不足时结束瀑布流，不复制卡片制造虚假丰富度。

### 4.2 查看整套

- 点击穿搭卡或「查看整套」进入对应详情。
- 返回首页时恢复原筛选和滚动位置。

### 4.3 选择单品

- 默认选择所有可售单品。
- 用户可以取消选择任一可售单品。
- 售罄或失效单品不可选择，并显示明确状态。
- 已选件数和合计价格随选择实时更新。

### 4.4 替换单品

- 点击「换一件」打开底部替换面板。
- 面板展示同品类相似款；原型以中性占位商品呈现。
- 选中替换款后关闭面板，详情列表和合计价格同步更新。
- 无替换结果时展示空态；请求失败时保留原单品并允许重试。

### 4.5 成交操作

- 「加入购物车」：至少选择一件可售商品时可用，完成后显示轻提示。
- 全部可售商品均被选中时显示「购买整套」；用户取消任一单品后显示「购买已选」。至少选择一件可售商品时可用，原型中展示确认反馈，不进入真实收银台。
- 未选择商品时两个操作均为禁用态，并说明需要先选择商品。

## 5. 组件与设计语言约束

本原型命中页面、模块、组件、组件元素和 Token 层级。优先复用：

- `common/md/组件/商品卡.md`
- `common/md/组件/标签栏Tab.md`
- `common/md/组件/按钮.md`
- `common/md/组件/货币／价格.md`
- `common/md/组件/营销标签 tag.md`
- `common/md/组件元素/布局.md`
- `common/md/组件元素/颜色.md`
- `common/md/组件元素/文字.md`
- `common/md/组件元素/圆角.md`
- `common/md/token/设计 Token.md`

约束如下：

- 颜色只使用已登记的语义色。
- 字号、行高、间距和圆角只使用已登记 Token。
- 商品图片保持比例，不拉伸。
- 标题和辅助信息按优先级截断，不压缩到未登记字号。
- 不编造商品事实、优惠、销量或营销背书。
- 「穿搭页」当前未登记为正式设计资产，因此原型保存在独立调试目录，不写回 Skill 的 `pages/` 或 `common/`。

## 6. 状态与异常处理

- 加载：首页和详情使用与最终布局同尺寸的骨架结构，避免跳动。
- 首页空态：说明当前场景暂无穿搭内容，并提供返回推荐的操作。
- 图片失败：显示固定比例的中性占位，不拉伸或塌陷布局。
- 商品失效：整件不可选择，保留标题和失效说明。
- 部分售罄：默认排除售罄商品，其余商品仍可购买。
- 全部不可售：成交操作禁用，提供返回浏览的操作。
- 替换失败：保留原商品，显示重试入口。
- 长文案：卡片标题最多两行，商品标题按组件规范截断；不得遮挡价格和按钮。
- 小屏和大字：优先保留图片、标题、价格和主操作，隐藏低优先级辅助信息。

## 7. 原型结构

原型采用独立、零依赖 HTML 文件，内部按职责拆分为：

- 首页视图：筛选、瀑布流与底部导航。
- 详情视图：造型信息、单品列表与成交栏。
- 替换面板：相似款选择和异常状态。
- 状态存储：当前场景、滚动位置、选中单品、替换结果和反馈提示。

视图之间只通过明确状态切换，不接入外部接口。刷新页面后恢复为默认推荐场景和默认整套选择状态。

## 8. 验收标准

- 用户能从穿搭瀑布流进入任一穿搭详情。
- 用户能勾选、取消选择和替换单品。
- 已选件数与合计价格能随操作正确更新。
- 用户能触发加入购物车，以及「购买整套」或「购买已选」反馈。
- 返回首页后筛选状态与滚动位置保持。
- 页面在手机宽度下无横向溢出。
- 长文案、图片失败、商品失效和替换失败不会破坏布局。
- 页面只使用已登记的颜色、字号、行高、间距与圆角 Token。
- 原型不改动电商设计语言核心样板和正式资产。

## 9. 交付物

- 一个可直接打开的高保真交互 HTML 原型。
- 一份简短的交互与状态说明。
- Token 与关键交互自测结果。
