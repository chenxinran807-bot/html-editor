# PRD → Figma → 交互 Demo 统一 Workflow 设计

## 1. 目标

让不懂设计、不懂 Figma 文件结构、也不懂本地路径的用户，以最低操作成本完成“PRD + 已有设计 → 高还原交互 Demo → 圈选修改 → 局部回改”。

日常主路径只有两个主动动作：

1. 在 Figma 中多选参考 Frame，运行“批量采集”。
2. 在 Agent 当前对话提供 PRD，并说：“根据当前 PRD 和刚采集的设计生成交互 Demo。”

“最低成本”不等于取消生成前确认。用户明确要求保留逐个确认多个问题，因此本设计优化的是每个问题的必要性、依据和回答成本。

## 2. 第一性原理与非目标

### 2.1 第一性原理

- 用户负责表达产品意图和选择参考内容，不负责搬运 manifest、素材路径、taskId 或云盘目录。
- 机器负责采集、绑定、校验、查找、下载、映射、注入和回归。
- 每个用户问题必须能改变核心结果；已在材料中明确的事实不要求用户重新描述。
- 至少确认页面范围、主用户动线、Frame 用途与还原强度。其他问题只在存在歧义时追加。
- 任何身份、任务或素材不一致都必须显式失败，不得用旧任务或推断结果伪装成功。

### 2.2 非目标

- 不新增一个需要用户理解的“总控 Workflow Skill”；`prd-demo` 仍是唯一入口。
- 不让 Figma 采集 App 绑定某一个 Agent 的私有后端或深链。
- 不把 html-editor 做成独立设计工具；它始终是注入业务 HTML 的标注浮层。
- 不要求当前版本接入在线 UI 框架、图标库、字体或参考图库；这些只能是可选增强。

## 3. 用户动线

### 3.1 首次配置（一次）

1. 安装 Figma 采集助手与 Figma 插件。
2. 登录飞书。
3. Agent 首次读取设计任务时完成飞书授权。
4. 安装或启用更新后的 `prd-demo` 与 `html-editor`。

### 3.2 日常生成

1. 用户在同一 Figma 文件中多选参考 Frame，运行“批量采集”。
2. Figma 插件一次导出；本机助手自动校验并上传。
3. 用户在 Agent 当前对话提供 PRD，并触发 `prd-demo`。
4. Agent 自动选择并校验当前用户最新完成的 Figma 任务。
5. `prd-demo` 一次只问一个问题，至少确认三个核心项。
6. 所有关键项确认后，用 3–5 行复述生成方案并直接开始生成，不再增加“是否开始”确认。
7. 输出高还原交互 Demo，并自动注入 html-editor。

### 3.3 日常修改

1. 用户在 Demo 中点击“标记修改”，点选或框选内容并保存。
2. 点击“完成标注”，复制修改要求。
3. 粘贴回原 Agent 对话。
4. Agent 只修改被标记条款，执行受影响范围回归，其他页面和未标记区域保持不变。

## 4. 组件职责

### 4.1 Figma 插件

- 读取用户当前多选的 Frame、Component、Instance、Group 或 Section。
- 一次导出 PNG、SVG、文字、图层元数据和可确认的 Token。
- 同一批内容共用一个 UUIDv4 `taskId`。
- 产出 unified manifest、`task.json` 和任务 ZIP。
- 不上传网络，不处理飞书身份，不决定生成页面范围。

### 4.2 Figma 采集助手

- 监听任务 ZIP，拒绝路径穿越、未登记文件、大小或 SHA-256 不一致。
- 使用当前飞书用户身份上传 `/prd-demo-tasks/{taskId}/`。
- 首次上传时确保任务根目录存在不可变的 `_PRD_DEMO_ROOT.json`，用于绑定根目录、协议版本与 `ownerOpenId`。
- 将 `ownerOpenId` 写入远端 `task.json`。
- 最后上传 `_COMPLETE.json`；它是任务可消费的唯一完成信号。
- 不修改已完成任务，不代替 Agent 做 PRD/Figma 映射。

### 4.3 prd-demo

- 作为唯一用户入口，读取当前对话 PRD 与最新可信设计任务。
- 建立 PRD 页面、状态和 Figma Frame 的候选映射。
- 管理逐个确认状态机和会话决策表。
- 将确认结果固化为可追溯合同，组织生成与质量门禁。
- 生成成功后自动调用 html-editor 包装器注入标注层。
- 生成独立消费回执，不修改 `task.json` 或 `_COMPLETE.json`。

### 4.4 html-editor

- 只采集修改意图，不直接修改业务原型。
- 用户界面只显示自然语言；机器交付内容保留页面、选择器、HTML 片段和参考图。
- 保持零运行时依赖、系统字体和内联 SVG；外部设计资源只能作为可选参考增强。

## 5. 身份与一致性

四个关键键：

| 维度 | 键 | 作用 |
|---|---|---|
| 用户 | `ownerOpenId` | 确认任务属于当前飞书用户 |
| 任务 | `taskId` | 绑定一次批量采集及消费回执 |
| 设计节点 | `fileKey + nodeId` | 防止同名 Frame、多个 Figma 标签或副本串稿 |
| 生成会话 | `sessionId` | 绑定确认进度、生成结果和消费回执 |

任一键不一致时停止消费，不允许静默拼接、降级为旧素材或改用其他用户任务。

当前对话中的 PRD 另计算稳定的 `prdFingerprint`。它不参与设计任务身份，但用于发现确认过程中 PRD 被替换或修改，防止旧答案套到新需求上。

## 6. 最新任务选择与校验

1. 使用当前用户身份按精确名称发现 `/prd-demo-tasks/` 根目录，并校验 `_PRD_DEMO_ROOT.json` 的协议版本和 `ownerOpenId`。
2. 枚举 `{taskId}` 子目录，只保留存在 `_COMPLETE.json` 的任务。
3. 读取 `task.json` 与 `_COMPLETE.json`，要求目录名、两份文件中的 `taskId` 一致。
4. 要求 `task.json.ownerOpenId` 等于当前用户 openId。
5. 校验 task/manifest schema、相对路径、文件大小、逐文件 SHA-256 和 `manifestSha256`。
6. 以 `_COMPLETE.json.completedAt` 降序选择最新任务；不得用 `task.json.createdAt` 代替。
7. 下载到会话隔离目录 `figma_export/incoming/{taskId}/`，再按 manifest capabilities 消费。

如果云空间存在多个同名目录，只允许选择唯一一个根标记合法且属于当前用户的目录；出现多个合法根目录时停止并要求用户选择，禁止合并目录中的任务或按更新时间猜测。

若最新任务损坏，默认拒绝。Agent 可以提出一次问题，说明任务时间和失败原因，询问是否检查上一条完整任务；未获用户确认不得自动回退。

## 7. 逐个确认状态机

### 7.1 决策分类

读取全部材料后，将决策分为：

- `determined`：PRD、manifest 或用户历史回答已明确；用于形成推荐，但三个核心项仍需确认。
- `pending`：缺少会改变核心结果的信息，需逐个确认。
- `conflict`：材料之间无法同时满足，必须明确指出冲突并让用户裁决。

### 7.2 固定顺序

1. **页面范围**：展示候选页面清单与推荐范围。
2. **主用户动线**：用一句可观察路径描述进入、操作、结果和返回。
3. **Frame 用途与还原强度**：逐 Frame 给出基础框架、严格还原、组件参考、交互状态或不采用的推荐绑定。
4. **追加问题**：仅在存在歧义时逐个确认关键组件形态、素材用途或显著视觉方向。
5. **生成摘要**：3–5 行复述页面、动线、Frame 绑定与关键交互，然后直接生成。

### 7.3 单问题契约

每轮只能问一个问题，且必须包含：

- 判断所依据的 PRD 条目或 Figma Frame；
- 一个明确默认推荐；
- 用户最终会看到什么或如何操作；
- 一句话可完成的回答方式。

回答写入 `sessionId` 对应的会话决策表，并持久化为 Agent 会话工作区中的 `workflow-state/{sessionId}.json`。状态至少包含 `taskId`、`prdFingerprint`、已确认项、下一问题和当前阶段。新回答与旧答案冲突时必须指出冲突，不得静默覆盖。授权、下载或工具中断后从下一未确认项继续，不重复提问。

如果确认过程中 PRD 内容改变，Agent 重新计算 `prdFingerprint`，只重新确认受影响的决策；无法判断影响范围时，明确说明原因并从页面范围重新确认，不能继续沿用整份旧决策表。

## 8. 生成、注入与消费回执

生成结果至少包含：

- 可直接预览的交互 HTML；
- 使用过的 PNG/SVG 等本地素材；
- 页面、动线、素材和确认答案的可追溯记录；
- 自动注入的 html-editor；
- 在工程化模式下的合同与验证结果。

成功后在远端任务目录新增：

```text
consumption/{sessionId}.json
```

字段至少包含：

```json
{
  "consumptionSchemaVersion": "1.0",
  "sessionId": "...",
  "taskId": "...",
  "prdFingerprint": "...",
  "agentUserOpenId": "...",
  "consumedAt": "...",
  "result": {
    "status": "completed",
    "demoUrl": "...",
    "artifact": "..."
  },
  "decisions": {
    "pageScope": [],
    "primaryFlow": "...",
    "frameBindings": []
  }
}
```

`task.json` 与 `_COMPLETE.json` 永不修改。回执上传失败不能伪装为完整闭环；Demo 可交付，但需明确提示回执未写入并允许重试。

## 9. 异常与能力降级

| 场景 | 行为 |
|---|---|
| 当前对话缺少 PRD | 暂停，只要求补充 PRD |
| 飞书未授权或授权过期 | 暂停在当前步骤；授权后续跑且不重复确认 |
| 没有 completed 任务 | 提示回到 Figma 批量采集 |
| 最新任务校验失败 | 拒绝；询问是否检查上一条完整任务 |
| PRD 与 Figma 页面范围冲突 | 在页面范围问题中明确冲突并裁决 |
| Agent 没有飞书能力 | 降级为任务文件夹链接或本地 ZIP，不声称自动发现 |
| 缺少 manifest capability | 明确标记未知，遵守能力降级，不推断成“设计中不存在” |
| html-editor 注入失败 | Demo 不算完整交付，修复或明确提供未注入版本与失败原因 |

真正的日常两步式只对“已完成首次授权且 Agent 具备飞书读取能力”的环境成立。其他 Agent 使用同一任务协议，但允许多一步显式交接。

## 10. 协议漂移修正

实现时必须同步修订现有 prd-demo 文档：

- 远端任务目录是 `/prd-demo-tasks/{taskId}/`，不是 `{userId}__{taskId}`。
- 用户身份从 `task.json.ownerOpenId` 校验，不从目录名前缀推断。
- 最新任务按 `_COMPLETE.json.completedAt`，不按 `task.json.createdAt`。
- `task.json` 永不回写 `consumedAt`；消费状态写入 `consumption/{sessionId}.json`。
- 云端任务是主路径；`~/Downloads/figma_export/incoming/` 只作为 Chrome 兜底或下载后的会话目录，不是统一事实源。

## 11. 对抗性验收

1. 同一分钟上传两个任务，只能按 `_COMPLETE.json.completedAt` 选中正确任务。
2. 上传一半且没有 `_COMPLETE.json` 的任务必须忽略。
3. `ownerOpenId` 属于另一用户的任务必须拒绝。
4. PNG、SVG、manifest 任一被替换，必须因哈希失败拒绝。
5. PRD 已明确页面范围时仍确认页面范围，但不得要求用户重新描述 PRD。
6. 用户回答第二个问题后授权失效，恢复后必须从第三个问题继续。
7. 多个 Figma 标签同时打开，不能改变已绑定任务。
8. 生成结果必须自动带 html-editor，原业务结构不能被包装器改写。
9. 标注一个元素后回改，其他页面与未标注区域不得变化。
10. 不支持飞书的 Agent 必须明确降级，不得伪装成两步式自动消费。
11. 新回答与历史确认冲突时必须指出并要求裁决。
12. consumption 回执失败时不得改写原任务或声称完整闭环成功。
13. 云空间出现两个同名且标记合法的任务根目录时，必须停下让用户选择，不能跨目录拼任务。
14. 确认过程中 PRD 被修改时，只保留未受影响的答案，并重新确认受影响项。

## 12. 实施范围与顺序

1. 修订并打包 `prd-demo`：最新任务消费、会话决策状态机、自动注入、消费回执与协议漂移修正。
2. 补齐 workflow 运行时与 fixture：本地任务解析器、哈希校验、任务选择和对抗性测试。
3. 对 `html-editor` 增加稳定交接元数据与局部修改回归约定；不改已确认的 macOS Overlay 主界面。
4. 对 Figma 采集助手只做必要的回执展示或协议字段补充，不重新设计采集链路。
5. 使用真实三 Frame 任务与真实 PRD 完成端到端验收，再生成安装包、用户说明和跨 Agent 降级说明。
