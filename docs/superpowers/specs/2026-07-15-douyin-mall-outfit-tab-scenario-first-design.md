# 抖音商城独立端穿搭 Tab：场景优先高保真原型设计

## 1. 产品目标

为抖音商城独立端设计一个面向男女混合用户的「穿搭」Tab。核心体验同时服务两个任务：用户可按通勤、约会、出游等场景快速找到整套搭配，也能继续浏览真人穿搭、主题合集和编辑搭配，获得持续的穿搭灵感。

原型采用“场景导航优先”方案。首页先回答“今天该怎么穿”，内容流再承接持续种草；购买能力放在搭配详情之后，不在首页抢占内容体验。

## 2. 用户与成功标准

### 2.1 目标用户

- 男女混合用户，不预设单一性别为主。
- 有明确场景需求，希望快速获得可执行的整套穿搭方案。
- 也愿意通过真人内容和主题合集发现新的搭配方向。

### 2.2 核心任务

1. 选择当前场景并浏览对应整套搭配。
2. 理解一套搭配的思路、适用人群和组成单品。
3. 替换不合适的单品，并将感兴趣的单品加入购物车。
4. 喜欢、收藏或关注感兴趣的穿搭内容。
5. 从详情返回后继续原位置浏览。

### 2.3 原型成功标准

- 用户能从首页完成“选择场景 → 查看整套搭配 → 查看或替换单品 → 加购”的主路径。
- 用户能继续下滑浏览真人穿搭、主题合集和整套搭配三类内容。
- 男女内容在首页有明确且自然的平衡，不强制用户先选择性别。
- 返回内容流时恢复原场景、筛选条件和滚动位置。
- 主要控件有可见反馈，不存在死按钮或仅改变地址的伪交互。

## 3. 信息架构

### 3.1 顶部区域

- 页面标题：穿搭。
- 右侧操作：搜索、消息。
- 主频道：按场景、适合我、博主推荐。
- 默认频道：按场景。

主频道保存各自的筛选状态和浏览位置。用户切换频道并返回时，恢复该频道离开前的状态。

### 3.2 场景导航

“按场景”首屏展示六个图形化入口：

- 通勤：清爽有精神。
- 约会：自然有氛围。
- 出游：松弛又上镜。
- 校园：轻松有活力。
- 运动：舒展不拖沓。
- 聚会：低调有亮点。

默认选中“通勤”。点击其他场景后，焦点搭配和下方内容流同步更新。

### 3.3 场景焦点区

当前场景下优先展示 2–3 套编辑精选搭配。首屏至少包含一套偏女性表达和一套偏男性表达，性别仅作为内容说明，不作为强制分区。

每套搭配展示：

- 完整造型图。
- 一句话搭配主题。
- 搭配亮点或适用人群。
- 单品数量。
- 查看搭配详情入口。

首页不展示未经业务确认的优惠、销量、最低价或营销承诺。

### 3.4 灵感内容流

场景焦点区下方采用双列瀑布流，混排三类内容：

1. 真人穿搭：强调作者、穿搭理由、喜欢与关注关系。
2. 主题合集：强调主题说明、内容数量和连续浏览。
3. 整套搭配：强调搭配解析、适用人群和单品数量。

三类卡片采用可感知的不同结构，避免所有内容套用同一商品卡模板。内容不足时自然结束，不复制卡片制造虚假丰富度。

### 3.5 底部导航

底部导航包含：首页、视频、穿搭、购物车、我的。“穿搭”处于选中状态，导航不遮挡内容或关键操作。

## 4. 页面设计

### 4.1 穿搭首页

首页由顶部导航、主频道、场景入口、场景焦点区、灵感内容流和底部导航组成。

视觉策略为“轻内容、强场景”：使用白色商城背景和深色正文，商城红仅用于选中态与关键动作；图片承担主要氛围，卡片减少厚重边框和阴影。首屏优先表达任务效率，下滑后增强内容社区感和连续浏览感。

### 4.2 真人穿搭详情

包含沉浸式图片、作者信息、关注入口、穿搭说明、适用场景、风格标签和关联单品。喜欢、收藏和关注状态与首页保持一致。

### 4.3 主题合集详情

包含主题说明、连续内容流和相邻主题推荐。用户可上下连续浏览，浏览到底后进入相邻主题，而非出现流程断点。

### 4.4 整套搭配详情

包含完整造型、搭配逻辑、适用人群、单品清单和底部加购操作。用户可点击单品查看信息，也可打开同类替代款弹层。

### 4.5 单品替换弹层

弹层展示当前单品和 2–3 个同类替代款。替代款只使用中性名称与占位信息，不生成虚构折扣或销量。选择替代款后，搭配详情中的单品清单和造型说明同步更新，并提供可见确认反馈。

## 5. 核心交互

### 5.1 场景与频道切换

- 点击场景后立即更新选中态。
- 焦点搭配和内容流先显示与最终卡片尺寸一致的短时骨架屏，再展示目标内容。
- 切换主频道后保存当前频道的筛选项和滚动位置。

### 5.2 内容反馈

- 喜欢：即时切换状态和计数展示。
- 收藏：即时切换状态，并使用非阻断轻提示确认。
- 关注：同一作者在首页与详情中的关注状态同步。
- 不感兴趣：从更多菜单触发，移除卡片并展示短时撤销入口。
- 撤销：将被移除卡片恢复到原位置。

原型使用本地状态模拟以上行为，不承诺真实账号同步或推荐算法效果。

### 5.3 详情与浏览恢复

- 点击三类内容卡分别进入对应详情。
- 返回时恢复来源频道、场景、筛选条件和滚动位置。
- 页面或 URL 状态变化必须伴随可见内容变化。

### 5.4 单品与加购

- 点击单品打开单品信息或替换入口。
- 选择替代款后同步更新当前搭配状态。
- 点击加入购物车后显示成功反馈并更新本地购物车数量。
- 原型不进入真实结算或支付流程。

## 6. 页面状态与异常处理

- 加载：使用匹配最终布局的骨架屏，避免明显跳动。
- 无结果：说明当前条件暂无内容，提供清除筛选和返回推荐。
- 加载失败：保留已展示内容，在内容流底部提供重试。
- 图片失败：使用相同比例的中性占位，不让布局塌陷。
- 操作失败：恢复操作前状态并提供重试，不显示阻断弹窗。
- 内容结束：明确提示当前主题已浏览完，并推荐相邻主题。
- 不感兴趣撤销：短时保留撤销入口，超时后完成移除。

## 7. 视觉与可用性规范

- 使用 390px 移动画布作为设计基准，并适配 320–430px 宽度。
- 不绘制手机外壳；原型本身即为移动页面。
- 颜色、字号、行高、间距、圆角、描边和图标使用电商设计语言中已登记的 Token 与资源。
- 图标使用自包含 SVG，不使用 Emoji、Unicode 字符或文字冒充图标。
- 主要触控区域不小于 44px。
- 图片明确比例、裁切方式和加载失败状态，不拉伸变形。
- 长文案采用明确的单行或多行截断规则，不遮挡关键操作。
- 未提供正式品牌素材时使用中性且可替换的本地素材，不宣称品牌视觉 1:1 还原。

## 8. 原型结构与数据流

原型采用零外部依赖的 HTML、CSS 和 JavaScript 单页实现，按职责拆分为：

- 页面与样式：承载移动布局、Token 映射和响应式规则。
- 内容目录：定义场景、内容卡、作者、搭配和单品的中性演示数据。
- 视图状态：保存频道、场景、筛选、滚动位置、喜欢、收藏、关注、移除卡片和购物车数量。
- 路由与渲染：根据当前状态渲染首页、三类详情和替换弹层。
- 交互处理：统一处理切换、反馈、返回恢复、替换和加购。

所有演示数据均为原型占位，不代表真实作者、商品、库存、价格、推荐算法或商业权益。

## 9. 可编辑与评审能力

- 支持交互演示模式，完整走通主路径。
- 支持全流程总览模式，横向展示关键页面和状态，便于截图评审。
- 提供画面导航和 hash 深链，可直达首页、详情、替换弹层及异常状态。
- 文案、颜色、图片、位置、大小、显隐和跳转目标使用稳定标识，便于后续编辑。

## 10. 验证方案

### 10.1 功能验证

- 场景与主频道均可实际切换。
- 三类内容详情可进入并正确返回。
- 喜欢、收藏、关注、不感兴趣、撤销、单品替换和加购均有可见反馈。
- 加载、无结果、加载失败、图片失败和内容结束状态可触发并恢复。

### 10.2 视觉与适配验证

- 在 320px、390px 和 430px 宽度下检查横向溢出、重叠和遮挡。
- 检查图片比例、文字截断、底部导航避让和弹层安全区。
- 核对颜色与视觉数值是否全部来自登记 Token。

### 10.3 可访问性与健壮性验证

- 主要操作具有正确语义、键盘焦点和可识别标签。
- 触控区域符合最小尺寸要求。
- 页面无控制台错误、无死按钮、无仅改变 URL 的伪交互。

## 11. 非目标

- 真实推荐算法、账号、关注、商品、购物车、库存、结算或支付接口。
- AI 搭配、AI 试穿或用户身体档案。
- 内容发布、审核和博主管理后台。
- 精确复刻未提供的抖音商城正式品牌资产。
