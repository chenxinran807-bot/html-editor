# HTML 画布编辑器设计规格

日期：2026-07-24  
状态：已完成方案确认，待书面规格复核

## 1. 目标

将 `html-editor` 从“记录标注意见的工具”升级为“可直接修改交互原型的 HTML 画布编辑器”：

- 用户可以像操作设计画布一样，直接修改文字、图片、样式、尺寸和位置；
- 小范围、确定性的修改不启动 Agent；
- 布局风险可见、可预览、可撤销；
- 复杂业务或结构修改转成平台无关的结构化意图，由 Mira、Aime 或其他 Agent 继续执行；
- 最终产物仍是包含多页面、多状态和交互逻辑的独立 HTML。

首版不追求复刻完整 Figma，而是优先解决高频局部修改、布局保护、可恢复保存和跨 Agent 交接。

## 2. 已确认的产品原则

### 2.1 画布优先

原型主体始终是视觉中心。编辑面板必须位于画布外侧并自动避让，不得遮挡当前选中元素。

### 2.2 最小改动优先

用户只想改一个小地方时，只修改当前对象。不得为了完成局部调整而无提示地重构父容器、相邻元素或其他页面。

### 2.3 直接修改与 Agent 修改分层

- 结果确定、作用范围清晰的修改直接写入 HTML/CSS；
- 可能改变布局语义的修改先预览并确认；
- 涉及业务逻辑、多页面状态或大规模结构重构的修改交给 Agent。

### 2.4 默认安全，允许主动自由

编辑器默认遵循 Flex、Grid、普通文档流和定位规则。用户可主动选择“自由放置”，但必须提前提示响应式和交互风险。

### 2.5 所有修改可解释、可撤销

“已直接修改”“待用户确认”“等待 Agent 修改”必须是三个不同状态。记录修改意图不等于修改成功。

## 3. 方案选择

### 3.1 备选方案

1. **自由画布模式**：所有元素任意拖放。操作自由，但容易破坏响应式布局和交互。
2. **严格布局模式**：只允许在现有布局规则内修改。安全，但用户会频繁遇到“拖不动”。
3. **混合模式**：默认遵循布局，明确安全的变更直接落地，危险变更先预览，用户可主动自由放置。

### 3.2 决策

采用混合模式。它同时满足“小改动足够快”和“复杂原型不被轻易改坏”。

## 4. 总体架构

系统分为三个职责独立的层：

### 4.1 直接编辑层

负责确定且局部的修改：

- 文案、图片；
- 字号、字重、行高、对齐、颜色；
- 背景、边框、圆角、阴影；
- 宽高、间距、显示隐藏；
- 复制、删除、简单排序；
- 安全范围内的拖动和缩放。

修改立即应用，并写入统一操作历史。

### 4.2 布局保护层

负责识别目标元素的布局上下文、推导安全操作并检查副作用：

- Flex / Grid；
- 普通文档流；
- 绝对定位；
- 固定定位；
- 无法可靠识别的复杂布局。

该层只输出“可直接执行”“需预览确认”或“应交给 Agent”的判断，不负责业务语义修改。

### 4.3 Agent 意图层

负责把无法安全直接完成的需求转换为结构化任务，例如：

- 新增或删除页面；
- 修改跨页面状态；
- 重构复杂组件；
- 修改业务流程；
- 修改原型数据和交互逻辑。

意图格式不绑定 Mira 或 Aime。任何能读取 HTML 与 JSON 的 Agent 均可继续处理。

## 5. 用户交互

### 5.1 基础操作

- 单击：选中元素；
- 双击文字：原位编辑文案；
- 双击图片：替换图片或调整图片；
- 拖动元素：安全移动、重排或自由放置；
- 拖动四角控制点：调整尺寸；
- `Shift`：锁定比例；
- 一键“正方形”：将宽高比设为 `1:1`；
- `Command+Z`：撤销；
- `Shift+Command+Z`：重做；
- `Esc`：取消当前操作。

常用小改动不要求打开属性面板。

### 5.2 界面布局

编辑界面由四部分组成：

1. 顶部轻工具栏：选择、撤销、重做、预览和保存；
2. 可收起的页面/状态导航；
3. 中央原型画布；
4. 画布外侧属性面板。

属性面板规则：

- 默认吸附在右侧，可切换至左侧；
- 打开时画布自动缩放并重新居中；
- 可收起为窄条；
- 窗口较窄时变为底部抽屉，并为画布预留空间；
- 选中靠近面板的元素时，面板自动切换到另一侧；
- 拖动面板时只允许吸附到预设空白区，不允许悬浮覆盖主体；
- 退出编辑、修改记录和保存进入统一工具栏，移除重复悬浮按钮。

## 6. 布局编辑规则

| 当前布局 | 默认拖动行为 | 直接修改对象 |
|---|---|---|
| Flex / Grid | 显示插入位置，改变顺序或对齐 | `order`、`gap`、对齐规则 |
| 普通文档流 | 显示前后插入线，改变节点位置 | DOM 顺序、外间距 |
| 绝对定位 | 显示参考线和距离，直接移动 | `left/top/right/bottom` |
| 固定定位 | 约束在当前视口内移动 | 固定位置与边距 |
| 复杂或不确定布局 | 仅预览，松手后确认 | 默认不写入 |

### 6.1 自由放置

用户主动选择“自由放置”后，元素可以脱离原布局并采用定位方式落到目标位置。应用前必须：

- 显示即将脱离的父布局；
- 提示可能影响响应式；
- 提供预览、确认和取消；
- 创建可完整撤销的单次操作记录。

### 6.2 缩放

- 图片、卡片、按钮可直接缩放；
- 文字容器默认改变容器宽度并自然换行，不拉伸字形；
- 正方形操作将目标宽高比设置为 `1:1`；
- 控件保留最小尺寸，避免文字、按钮和触控区失效；
- 操作完成后检查溢出、遮挡、不可点击和视口越界。

如果副作用无法自动消除，用户可选择保留、撤销或交给 Agent；编辑器不得擅自修改其他区域。

## 7. 修改记录与数据协议

### 7.1 直接修改记录

每条记录至少包含：

```json
{
  "id": "edit-0001",
  "page": "bookshelf",
  "state": "default",
  "target": "book-cover-1",
  "operation": "resize-and-move",
  "before": {
    "width": 160,
    "height": 216,
    "position": "flow"
  },
  "after": {
    "width": 160,
    "height": 160,
    "position": "absolute",
    "right": 24,
    "top": 24
  },
  "scope": "current-element",
  "status": "applied",
  "risk": "confirmed",
  "reversible": true,
  "createdAt": "2026-07-24T14:00:00+08:00"
}
```

默认保留最近 100 步。连续的移动与缩放可合并成一个用户操作，以便一次撤销。

历史以当前 HTML 文件的稳定文档指纹为命名空间，编辑过程中保存在浏览器本地存储；导出“可继续编辑版”时同时嵌入 HTML 内的编辑元数据。再次打开同一版本时恢复历史，打开“干净交付版”时不加载编辑历史。页面与状态必须使用 HTML 中的稳定标识；没有稳定标识时，编辑器在首次进入编辑模式时生成并持久化。

### 7.2 Agent 意图

无法安全直接执行的修改写入 `edit-intents.json`：

```json
{
  "schemaVersion": "1.0",
  "intents": [
    {
      "id": "intent-0001",
      "page": "bookshelf",
      "state": "default",
      "target": "book-card-1",
      "request": "把封面改成正方形并放到卡片右上角",
      "status": "pending-agent",
      "appliedDirectly": false,
      "reason": "需要重构卡片内部布局",
      "context": {
        "originalLayout": "flex-row",
        "selectedElement": "book-cover-1"
      }
    }
  ]
}
```

目标元素必须使用稳定标识。找不到原元素时明确报告冲突，不猜测其他节点。

## 8. 保存与恢复

采用双模式保存：

### 8.1 默认导出新文件

- 无需额外授权；
- 自动增加版本或时间戳；
- 不修改原文件；
- 作为首选稳定路径。

### 8.2 授权后覆盖原文件

- 仅在浏览器文件访问能力可用且用户明确授权后启用；
- 覆盖前在内存中保留完整旧内容，并优先导出一个带 `.backup.html` 后缀的恢复文件；
- 写入失败时不改变原文件，并自动回退为导出新文件；
- 外部修改导致版本冲突时停止覆盖并提示用户。

### 8.3 导出类型

- **可继续编辑版**：保留编辑器运行时、历史和 Agent 意图；
- **干净交付版**：移除编辑面板、选择框、参考线等编辑辅助层，只保留原型及已应用修改。

两种导出都必须保留原有多页面、多状态、页面跳转、弹层和业务交互。

## 9. 错误处理

- 找不到目标元素：停止当前修改，报告冲突；
- 布局类型不确定：降级为预览确认；
- 修改后出现溢出、遮挡或不可点击：显示问题并让用户选择保留、撤销或转 Agent；
- 原文件在编辑期间发生外部变化：禁止静默覆盖；
- Agent 执行失败：保留所有已经完成的直接编辑；
- 保存失败：保留内存中的编辑状态并回退下载；
- 交互回归失败：不得标记为交付成功。

## 10. 首版范围

### 10.1 必须实现

- 直接编辑文字、图片与基础视觉样式；
- 拖动、四角缩放、比例锁定和正方形；
- Flex、Grid、普通文档流和定位布局的基础识别；
- 插入位置、对齐线、距离提示与基础吸附；
- 默认安全调整和主动自由放置；
- 画布外属性面板与自动避让；
- 撤销、重做、修改记录与恢复点；
- 新文件导出和授权覆盖；
- 可继续编辑版与干净交付版；
- 平台无关的 Agent 意图；
- 保留多页面、多状态和交互。

### 10.2 明确不包含

- React、Vue 等源代码级双向同步；
- 任意复杂 DOM 重构均可拖拽完成；
- 多人实时协同；
- 完整设计系统或组件库管理；
- 矢量路径编辑；
- 无授权静默覆盖本机文件；
- 所有复杂修改都无需 Agent。

## 11. 验收标准

首版至少通过以下真实任务：

1. 双击标题修改文案，并完成撤销与重做；
2. 修改单个按钮颜色、圆角和字号，不影响其他按钮；
3. 将“置身事内”封面调整为正方形并移动到卡片右上角；
4. 在 Flex 卡片列表内拖动卡片并正确改变排序；
5. 属性面板始终不遮挡当前选中元素；
6. 在多个页面和状态间切换后，历史仍绑定正确目标；
7. 导出后页面跳转、弹层和按钮交互正常；
8. 覆盖失败时原文件不变，并可下载新版本；
9. 复杂结构调整生成准确的 Agent 意图，不显示为已完成；
10. Mira、Aime 或其他 Agent 能读取同一交接格式继续处理。

## 12. 成功指标

- 高频局部修改无需 Agent 即可完成；
- 用户能明确区分已应用、待确认和待 Agent 三种状态；
- 每个直接操作都可以完整撤销；
- 保存结果是独立可运行的交互 HTML；
- 编辑面板不遮挡原型主体；
- 局部修改不破坏其他页面和核心交互。

## 13. 实施拆分建议

本规格可以进入一个实施计划，但实现时必须按独立模块拆分，避免继续扩大单文件注入脚本：

1. selection 与稳定目标标识；
2. patch 与 history 引擎；
3. layout interpreter；
4. canvas overlay 与 snapping；
5. inspector 与 dock layout；
6. persistence 与 exporter；
7. Agent intent adapter；
8. interaction regression checks。

模块通过明确数据接口协作，现有标注能力作为兼容入口逐步迁移，不在首版无关重构其他 Skill。
