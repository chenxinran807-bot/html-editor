# PRD to Demo End-to-End Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用真实三 Frame 任务和 PRD 证明“批量采集一次 + Agent 一句话”能可靠生成、标注并局部回改交互 Demo。

**Architecture:** 在三个子系统通过各自测试后，用脱敏 fixture 做可重复 CI，再用用户已确认的真实“视频 tab、穿搭 feed（无形象）、穿搭详情页”任务做人工链路验收。所有成功声明都由 task identity、哈希、会话状态、注入标记和页面回归证据共同支撑。

**Tech Stack:** Node test runner、Python `unittest`、真实 Figma/Lark 任务、浏览器视觉与交互检查、SHA-256。

### Task 3: Run the real three-Frame acceptance

**Files:**
- Create: `workflow/REAL-E2E-REPORT.md`
- Create: `workflow/evidence/README.md`

- [ ] **Step 1: Confirm prerequisites without exposing secrets**

Verify helper `2.0.2`, html-editor `1.2.0`, current-user Lark authorization, and the updated prd-demo Skill. Record only versions and pass/fail—not tokens or open IDs.

- [ ] **Step 2: Capture the three approved Frames once**

In Figma select exactly “视频 tab、穿搭 feed（无形象）、穿搭详情页” and run batch capture. Record taskId, fileKey, three nodeIds, completion timestamp, and helper success screenshot.

- [ ] **Step 3: Trigger from the Agent in one sentence**

Provide the real PRD in the current conversation and say: `根据当前 PRD 和刚采集的设计生成交互 Demo。`

Verify the Agent chooses the same taskId and asks one question at a time: page scope, primary flow, then frame bindings. Interrupt authorization after question 2 in a controlled test and prove question 3 resumes.

- [ ] **Step 4: Verify generated Demo**

Check all three pages, primary flow, strict/reference mappings, real PNG/SVG reuse, no redraw of provided assets, key empty/loading/error/success states, responsive preview, and automatic html-editor injection.

- [ ] **Step 5: Verify one annotation round trip**

Annotate one target on the detail page, copy once, paste to the same Agent, and apply the patch. Compare normalized HTML/screenshots for the other two pages before and after; they must be unchanged.

- [ ] **Step 6: Verify receipt and degradation**

Confirm `consumption/{sessionId}.json` exists and task/completion hashes remain unchanged. In a second Agent without Lark Drive, confirm it asks for the folder link or local ZIP and never claims automatic discovery.

- [ ] **Step 7: Write the evidence report**

For each requirement, record authoritative evidence path, observed value, and pass/fail. Private PNG/SVG remain outside Git; `workflow/evidence/README.md` records SHA-256 and secure location only.

- [ ] **Step 8: Commit non-private evidence**

```bash
git add workflow/REAL-E2E-REPORT.md workflow/evidence/README.md
git commit -m "docs: record real prd demo workflow acceptance"
```
