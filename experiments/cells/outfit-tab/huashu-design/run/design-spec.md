# 穿搭 Tab · 原生实验设计规格

## 需求重述

这不是一个普通的商品瀑布流，而是一条帮助年轻女性完成穿搭决策的短链路。用户进入穿搭 Tab 时并不只是想看商品，她首先要知道今天的场景该穿什么，接着判断这套是否适合自己的身型、肤色与生活方式，最后才会关心能否买到同款、有没有更低价的替代，以及自己穿上会怎样。冻结输入显示当前主要问题是内容吸引度和解释力不足：人均停留 22 秒、主动点击率 2.8%，试穿入口点击不足 2%。因此原型必须把判断理由前置到 feed 卡片，把适合人群、配色公式和避雷放在详情决策区，再让商品、平替、AI 搭配与试穿成为自然的下一步。基于这个理解，本实验用一个完整主流程和三个可见视觉方向覆盖固定任务，同时保持所有产品图片与事实都来自冻结输入。

## 输出与约束

- 输出：单文件 HTML，可通过本地 HTTP 或 `file://` 打开；主画布含 393×852 iPhone 15 Pro 逻辑屏。
- 受众：需要日常、通勤、出游穿搭灵感，且关心身型适配与预算的年轻女性。
- 核心板块：一级穿搭入口；二级场景/身型分类；理由型 feed 卡；适合人群；配色公式；避雷提醒；商品同款/平替；AI 继续搭与 AI 试穿入口。
- 真实资产：只引用冻结的 `input/assets/image-009.png`、`011.png`、`012.png`、`013.png`；不新增网络图片。
- 禁区：不虚构真实库存、交易结果、AI 生成结果或产品照片；不使用 emoji 作为业务图标；不手写另一套设备外壳。
- 视觉温度：温暖、可信、像有经验的造型师在旁批注，而不是冷冰冰的货架。
- 视觉母题：试衣镜旁的造型师批注。暖纸底承担私人建议感，酒红承担判断与行动，细线承担公式化解释。

## Form 推导五问

1. 叙事角色：feed 是发现与筛选；详情是解释与决策；底部 sheet 是行动确认。
2. 观众距离：10 cm 手机距离，正文不小于 13px，关键判断 16–26px。
3. 视觉温度：温暖、编辑感、可信，避免促销红与多色标签噪音。
4. 容量估算：feed 首屏只呈现一张主卡与一句理由；详情用纵向章节承载高密度信息，避免同屏挤压。
5. 视觉母题：穿搭内容独有的「造型师批注 + 配色公式」，而非通用商城卡片。

## 三个结构性独立方向与选择

1. 秒数轮盘：实验开工秒数为 21，`21 % 20 + 1 = 2`，命中网页风格库第 2 项 Neo-Brutalism。方向一采用粗黑描边、硬阴影、撞色块与单列信息流，真实文件为 `artifact/direction-1-roulette.html`。
2. 现实标杆：冻结调研已核验小红书是「内容端可逛性天花板」，并明确其卡片与笔记混排、内容背书强。方向二迁移双列策展与理由先行，不复制其品牌视觉，真实文件为 `artifact/direction-2-benchmark.html`。
3. 最佳设计师锚点：Collins。方向三使用编辑级层级、单一酒红批注和内容驱动排版，把「解释为什么适合」塑造成产品签名，真实文件为 `artifact/direction-3-designer.html`。

自主选择标准：任务可理解性 30%、内容可信度 25%、视觉辨识度 20%、交互完整度 15%、迁移稳定性 10%。方向三在解释层级、冻结图片主导、单色批注母题和移动端可读性上最均衡，因此选为主版，并进一步实现 `artifact/index.html` 的 4 屏概览。三方向截图分别为 `qa/screenshots/direction-1.png`、`direction-2.png`、`direction-3.png`。

## 主版结构与交互纪律

- 默认平铺 4 个主屏：场景 Feed、适配详情、商品承接、AI 入口；四台均使用从 `vendor/huashu-design/assets/ios_frame.jsx` 移植的 `iosFrameStyles` 与 `IosFrame` 组件结构。
- 每台可操作分类、卡片、喜欢/减少此类、返回、商品平替和 AI 入口；未覆盖的一级 tabs 与底栏入口显式 disabled，避免伪交互。
- 分类完整覆盖 3 场景（日常、通勤、出游）和 3 条件（小个子、梨形、黄黑皮）。
- 冻结图片在构建时 base64 内嵌；4 个 HTML 均不依赖绝对路径、外部 CDN 或网络资源。
