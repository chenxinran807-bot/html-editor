# 视觉方向探索

仅在进入视觉阶段时读取。

## 路由

- 用户提供了明确视觉目标（设计稿、截图、指定设计系统），且没有要求重设计：采用 `reference-led`，按绑定关系还原，**不得强制探索**。
- 没有明确视觉目标，或用户明确要求重设计/换方向：采用 `explore`。

## Explore 硬门槛

1. 为同一个关键页面生成**恰好 3 个**彼此可辨识的真实视觉方案，使用同一视口、同一内容和同一状态。
2. 每个方案必须是可查看的图片或可渲染页面；不得用色板、关键词或文字卡片冒充。
3. 给方案 A/B/C 各写一句可感知差异，不写空泛风格词。
4. 把三张最终 PNG 保存到工作目录并写 `visual-options.json`。校验方案数、唯一 ID、产物存在性和真实像素尺寸；**不得凭声明尺寸**或聊天界面的“Generated”数量判定通过。
5. 必须实际运行以下门禁，退出码非零时只重生成失败方案，禁止向用户声称完成：

   ```bash
   python3 scripts/prototype_pipeline.py validate-visual visual-options.json --width 390 --height 844
   ```

6. 只有命令输出 `OK`、三张产物**全部校验通过**，才能统一展示并让用户选择。
7. 用户可以选择一版或明确组合，例如“A 的结构 + C 的配色”。保存选择后才进入用户动线图。
8. 用户选择后立即计算并保存入选 PNG 的 SHA-256，同时记录确认消息 ID。此后该文件为只读基准，不得被 QA、修复或实现阶段覆盖；需要换图时必须重新展示并获得用户确认。

生成工具一次只能返回一张图时，依次生成三张并在全部完成后统一展示。
