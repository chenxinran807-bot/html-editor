# 生成前逐题确认

## 固定三问

以下三个核心决策**不可跳过**，且一次只问一个：

1. `pageScope`：页面与状态范围。
2. `primaryFlow`：进入、操作、结果和返回组成的主用户动线。
3. `frameBindings`：每个 Frame 的用途与还原强度。

先读完 PRD、截图、manifest 和历史回答。材料已明确时，不让用户重述；把材料结论变成默认推荐，用户只需回复“按推荐”或一句纠偏。低影响字号、圆角、阴影和平台惯例由 Agent 决定，不追加问题。

## 单问题契约

每轮只出现一个问题，并包含四项：

- **依据**：引用 PRD 条目、页面名或 Frame 名。
- **推荐**：只给一个默认方案。
- **用户结果**：说明用户最终看到什么、如何操作。
- **回答方式**：保证一句话能回答。

示例：

```text
【页面范围】
依据：PRD 包含首页到详情的链路；本次采集有“视频 tab、穿搭 feed（无形象）、穿搭详情页”。
推荐：生成这 3 个页面，并补齐 feed 进入详情的跳转。
用户结果：打开 Demo 后可从视频 tab 切到穿搭 feed，再进入详情页并返回。
回复“按推荐”，或只说要增删的页面。
```

## 状态推进

把每次真实回答写入 `workflow-state/{sessionId}.json`：

```text
pageScope → primaryFlow → frameBindings → 必要的追加问题 → ready-to-generate
```

- 不得一次抛出多题或整页问卷。
- 不得把沉默、历史推断或默认值写成“用户已确认”。
- 不得在三个核心问题完成前生成。
- 新答案与旧答案冲突时，指出冲突并要求显式替换，不能静默覆盖。
- 授权或工具中断后读取状态文件，从下一题继续。

## 追加问题门槛

仅当答案会改变页面结构、核心组件类型、关键素材用途或显著视觉方向时追加。每次仍只问一个，并记录 `evidence`。

PRD 与 Figma 冲突时，把冲突放进当前对应问题：

- 页面不一致 → 放进 `pageScope`。
- 路径不一致 → 放进 `primaryFlow`。
- Frame 含义或还原方式不一致 → 放进 `frameBindings`。

不要因为参考图没展示 PRD 新模块就自动判定冲突；先判断它是否只是未覆盖状态。

## PRD 中途改变

重新计算 `prdFingerprint`：

- 能判断影响范围：只删除受影响答案，保留其余确认。
- 无法判断影响范围：说明原因，从 `pageScope` 重新确认。
- 禁止把旧 PRD 的完整决策表直接套到新 PRD。

## 开始生成

所有问题完成后，用 3–5 行复述：页面范围、主流程、Frame 绑定、关键状态。复述后直接生成，不再增加“是否开始”确认。
