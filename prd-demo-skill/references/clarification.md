# 轻量确认（逐个问题依次确认）

从全部材料中先找答案，只确认高影响缺口。已在材料中写清的不问，低影响细节直接标 `open`，不打扰用户。

## 核心原则：一次只问一个

把未决项按影响度排序，**每轮只向用户抛当前最高影响的那一个问题**，附一个默认推荐答案，用户一句话确认或纠偏；得到答复后再问下一个。

推进顺序（高→低）：

1. 核心页面 / 信息架构
2. 主用户动线
3. 关键组件形态
4. 图片 / 素材用途
5. 视觉方向

**禁止**：一次性抛长问卷、大批量 A/B/C 选项、一屏几十项让用户逐条回答。

**why**：逐个确认让用户每次只做一个决定，认知负担低、来回更少，贴合产品经理边看边定的真实习惯；一次性大批量抛出会让用户难以聚焦、容易漏答或放弃确认。

## 单问题表达

每个问题都要说清：默认推荐是什么、用户最终会看到什么、点击后发生什么。用最轻媒介表达，但**只聚焦当前这一个问题**：

- 页面关系：Mermaid。
- 单页布局：带编号的字符线框。
- 视觉摘要：色块角色、组件短标签、图片媒介。
- 精细确认图：仅在必要或用户要求时生成。

## 单问题确认话术示例

```text
【问题 1 / 关于信息架构】
推荐：首页用「三个等宽文字 Tab（各占 1/3）」承载 推荐 / 关注 / 附近 三个频道。
你看到的：进入首页即停在「推荐」Tab，点其他 Tab 切换对应 Feed。
是否按此推荐？如需调整回一句即可（如「改成两个 Tab，去掉附近」）。
```

用户确认或纠偏后，再抛下一个问题（如主用户动线），依次推进。未提及的低影响项按推荐执行，不再逐条追问。

## 何时必须暂停

以下内容缺失且会改变结果时，必须停下、等用户对当前这一个问题的真实回答，不能自答、不能把沉默当确认：核心页面、父子层级、主用户动线、关键组件类型、图片用途、显著视觉方向，或 PRD 与参考图无法同时满足的冲突。

不要因为参考图没有展示 PRD 新模块就制造冲突。不要确认低影响字号、圆角、阴影或常规平台细节。
